# Seed data (temporary)

Synthetic data for the HEDIS POC. **No real patient data.** This folder is temporary and will be removed
once real pipelines exist.

Everything here is generated from one file, `scripts/seed/scenario.py`, so all parts agree with each other.
Rebuild it all (identical output every time):

```
pip install -r scripts/seed/requirements-seed.txt
python scripts/seed/gen_all.py
```

## What is here

| Folder | Contents | Used by |
|---|---|---|
| `synthea/csv/` | Synthea 3.x format patient data (patients, encounters, conditions, observations, procedures, medications, payers, payer_transitions, organizations, providers). 426 people: 26 scenario members and 400 background members | Engine services (`measure_calc`, `gap_identifier`) |
| `engine/engine_run_MY2026.json` | What the engine should output for MY 2026: run metadata, per-measure totals and 330 gaps | Gap import (US-01 T3) |
| `measures/measures.yaml` | The 10 measure rules, windows, thresholds and prompt templates (SME review pending) | Measure library (US-01 T4), AI prompts |
| `measures/star_cut_points.json` | Star weights and the final 2027 cut points (CMS 2027 Technical Notes), used as the prior-year proxy for MY 2026 | Priority and impact (US-05) |
| `members/` | Members, organizations (with practice closure rates), providers, engagement (next visit, last contact) | App database, prioritization |
| `documents/` | 41 evidence documents in 8 formats plus `manifest.json` with the true text of each | Intake and conversion (US-02), AI extraction (US-03) |
| `documents/samples/` | Intake test files: mixed PDF, ZIP bundle, email with attachment, JPEG disguised as PDF, exact duplicate | File intake tests (US-02 T1) |
| `structured/` | CSV lab export and Excel vitals sheet with deliberate bad rows | CSV and Excel import (US-02 T4) |
| `expected/expected_findings.json` | The correct outcome for every gap: evidence to find, traps to avoid, final status | Scoring the AI and the review flow |

## The scenario in short

- **43 scenario gaps** cover all 10 measures with a case to approve, traps the AI must not propose, and
  exclusions. Their evidence exists **only in documents**, never in the structured data.
- **287 background gaps** have no documents. They stay open for outreach.
- Document formats: plain text (16), digital PDF (10), scanned PDF (2), phone photos (5, including poor light
  and blurry), handwritten notes (2), Word (4), fax TIFF (1), portal screenshot (1).
- Two documents have no member ID (`D-502` should match M-005 by name and date of birth; `D-9001` matches nobody).
- `D-805` is a near-duplicate of `D-801` from a different source.
- `G-0039` and `G-0040` close from the CSV and Excel files, without AI.

## Loading into the database

One-time setup of a local PostgreSQL database and `.env` (asks for your `postgres` admin password once;
uses an existing database of that name or creates it, and never empties an existing one):

```
powershell -ExecutionPolicy Bypass -File scripts/db/create_local_db.ps1 -DbName HEDISPOCDB
```

Then create the schema, check the database rules and load the data:

```
python -m alembic -c db/alembic.ini upgrade head
python -m pytest tests/db -q
python scripts/db/load_seed.py            # add --reset to empty and reload
```

The loader fills the team schema (see `docs/design/schema-alignment.md`):

| Seed file | Tables |
|---|---|
| `members/members.csv` | `patient` (member ID in `mrn`), `fhir_resource_raw` (names), `coverage` |
| `members/organizations.csv`, `providers.csv` | `organization` + `organization_quality`, `practitioner` |
| `members/engagement.csv` | `encounter` (planned visit, last contact) |
| `measures/` | `measure_definition` + `measure_rule`, `measure_star_weight`, `star_cutpoint` |
| `engine/engine_run_MY2026.json` | `engine_runs`, `measure_result` (one row per patient per measure), `care_gap` + `care_gap_detail` (seed code such as `G-0001`) |
| `documents/manifest.json`, `structured/` | `source_files`, `document_reference` + `document_conversion` |

Documents and structured files load as received files with status `pending`. Converting them to pages
is the job of the US-02 converters: `python -m services.document_intake.cli process-pending`.

## Known limits

- Synthea-format files are generated by our script (Java is not installed, so real Synthea was not run).
  Headers match Synthea's own `CSVConstants`. Some SNOMED, LOINC and RxNorm codes are plausible but not
  checked against a terminology server.
- Measure rules are built from public sources, not the licensed NCQA specification. See `verify_before_use`
  in `measures.yaml`.
